# high、xhigh 与模型路由的量化评测协议

## 1 研究问题

本项目不问“xhigh 总体强多少”
它问四个可测问题

1. 对每类软件生命周期任务，哪一条模型和 effort 路线达到最低可接受失败率
2. 从 high 升到 xhigh 的边际质量增益和边际令牌、时延、工具循环是多少
3. 路由器错误造成的损失，是否大于模型或 effort 本身的差异
4. 任务合同、上下文压缩和验收器强度，是否改变最优路线

## 2 为什么没有统一百分比

reasoning effort 的效果受以下因素交互影响

- 任务类别和步骤位置
- 模型层级
- 上下文长度和噪声
- 工具可用性
- 验收器强度
- 错误是否会在长轨迹中传播
- 停止条件和允许范围

因此 high 到 xhigh 的差异应表示为条件函数

```text
DeltaQuality = f(model, task_class, context, tools, verifier, phase, risk)
```

## 3 实验矩阵

### 因子

- 模型：Luna、Terra、Sol
- effort：medium、high、xhigh，按宿主实际支持组合
- 策略：quality_first、guarded_high、balanced
- 上下文：完整长上下文、压缩交接包
- 验收器：弱、强

### 任务分层

- 外部调查与证据综合
- 立项收敛与架构裁决
- 首个纵向切片
- 日常功能实现
- 跨模块复杂实现
- 可复现缺陷调试
- 非显然根因调试
- 代码与发布审查
- 批量机械修改

不要把这些任务混成一个总分

## 4 最小可行试验

第一阶段使用 30 到 50 个任务模板，每个模板至少覆盖三种路线

- 日常或机械任务每个配置至少 3 次运行
- 高方差复杂任务每个配置至少 5 次运行
- 同一模板采用随机交叉顺序，避免时间、代码库状态和缓存偏差
- 固定初始 commit、任务合同、工具权限、环境和验收器
- 每次运行使用独立分支或隔离工作树

样本量不要用一个固定大数替代功效分析
先做 pilot 估计方差，再用顺序检验或贝叶斯停止规则追加样本

## 5 主要指标

### 质量

- 验收通过率
- 严重缺陷率
- 回归率
- 范围外修改率
- 事实或证据错误率
- 发布后逃逸缺陷

### 效率

- 输入、缓存输入、输出和 reasoning tokens
- 工具调用次数
- 首次有效产物时间
- 总完成时间
- 返工轮次和返工分钟
- 上下文增长量

### 路由

- 欠路由率：配置不足导致失败
- 过路由率：更低配置已稳定通过但仍使用更高配置
- 升级延迟：出现证据后多久才升级
- 路由后悔值：相对 oracle 最低充分路线的预期损失
- 推荐覆盖率与用户覆盖原因

## 6 统计模型

### 二元结果

用混合效应逻辑回归或贝叶斯层级逻辑模型

```text
pass ~ model * effort * task_class + context_mode + verifier_strength
       + (1 | task_template) + (1 | repository)
```

### 连续结果

令牌、时延和返工时间使用对数变换后的层级模型，或稳健回归

### 配对差异

同一任务模板比较 high 与 xhigh

- 报告绝对百分点差
- 报告相对风险
- 报告 95% 置信区间或后验区间
- 同时报告令牌和工具调用差

### 非劣效门

常规实现可设置例如 2 个百分点的非劣效界限
该数值是产品决策，不是通用科学常数

## 7 预期损失函数

不计成本时仍需要计算失败与返工

```text
ExpectedLoss(route) =
    P(severe_failure | route) * severe_failure_cost
  + P(ordinary_failure | route) * rework_cost
  + P(scope_violation | route) * governance_cost
  + latency_weight * latency
  + token_weight * credits
```

质量优先用户可以把 `token_weight` 设为接近零，但不能把范围外修改和不可逆错误的代价设为零

## 8 置信度校准

路由器应预测“通过验收的概率区间”而非只输出标签

评估

- Brier score
- Expected Calibration Error
- 可靠性图
- 按任务类别的覆盖率
- 分布外任务的拒绝或升级率

当前 v0.1 只提供启发式 `policy_confidence`
在足够本地数据前，禁止输出伪精确概率

## 9 影子评测

对可复现且风险低的 10% 到 20% 任务，在隔离环境运行一档更低路线

例如

- Sol xhigh 主运行，Sol high 影子运行
- Terra high 主运行，Terra medium 影子运行
- Terra xhigh 主运行，Sol high 或 Terra high 影子运行

影子运行不得写入同一工作树或生产系统
只比较最终产物、测试、范围和用量

## 10 需要特别研究的交叉点

- Terra xhigh 与 Sol high 谁在“边界明确但复杂”的实现上更好
- Sol high 与 Sol xhigh 在“首个纵向切片”上的边际增益
- 压缩交接包是否比提升 effort 更能改善通过率
- 强验收器是否允许可靠降档
- 长轨迹中哪一步的欠推理最容易导致错误传播
- 高 effort 是否增加范围漂移、重复搜索和工具循环

## 11 发布标准

研究结果至少包含

- 冻结的任务模板和初始 commit
- 完整路由配置与模型快照日期
- 原始结果和失败分类
- 统计脚本
- 任务级别结果，而非只给平均分
- 对未评测模型版本和宿主差异的限制说明

只有在这些条件满足后，才把规则从“经验预设”升级为“经本地数据校准”
